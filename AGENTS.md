# Project operating instructions

Before changing this project, read `PROJECT.md`, `docs/06-handoff/current-state.md`, `docs/06-handoff/decision-record.md` and the relevant experiment document. Before proposing a niche, topic slate or channel launch, also read `docs/01-product/youtube-subject-research.md` and `docs/01-product/topic-selection-framework.md`.

## Canonical rules

- Treat the v2.1 hybrid character system as canonical: static cels by default, two-to-four-pose sequences for limited actions, and performance plates only when motion carries meaning.
- Do not revive the skeletal SVG rig unless the user explicitly requests a comparison test.
- Preserve approved character identity: egg-shaped head, sparse hair, long rounded nose, minimal facial marks, teal jacket, coral trousers, black shoes and economical dark linework.
- Use Remotion for whole-cel and whole-plate transforms, staging, camera, backgrounds, props, text, transitions, texture and rendering.
- Do not interpolate facial anatomy or bend a static raster cel.
- Prefer stepped or held timing over constant motion.
- Keep each scene beat to one dominant visual action.
- Convert approved green-screen art to transparent PNG assets once; do not key it repeatedly at render time.
- Convert approved green-screen performance clips to one normalized production asset; do not repeat manual keying for every scene.
- Choose the cheapest character treatment that communicates the beat convincingly. Do not use continuous performance merely to avoid stillness.
- Never overwrite an approved cel. Add a version or a new pose name.
- Keep diagnostics and production compositions separate.
- Never import production artwork from `assets-source/` or a marketplace package path. Production code may use only paired, approved objects in `assets-canon/`.
- Every canonical object requires `<name>.svg` and `<name>.meta.json` with the same basename.
- Preserve raw packages unchanged under `assets-source/_packages/`; normalize copies, never originals.
- Use stock primarily for mundane objects and set dressing. Everyman remains custom; technical cutaways are custom or reference-adapted; maps are programmatic; charts and diagrams are generated by Remotion.

## Required verification

- Run `npm run lint` after code changes.
- Render representative stills at the beginning, pose transition and end of each new sequence.
- Render the full composition before declaring an experiment complete.
- Visually inspect silhouette, matte edges, registration, identity consistency and safe framing.
- Record the result in `docs/05-experiments/experiment-log.md`.

## Production constraint

Every decision must support an eventual eight-hour weekly production ceiling. Reject techniques that look good only through per-shot manual repair.

- Do not recommend subjects merely because they are enumerable or easy to animate. Require a clear general-audience human stake.
- Separate observed public performance from hypotheses about why it occurred. Timestamp future data research.
