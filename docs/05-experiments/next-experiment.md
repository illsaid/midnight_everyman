# Next experiment - second-topic reuse benchmark

## Objective

Build a second 45-75 second narrator-led systems explainer using the architecture validated by `WrongFuelSystemsPilot`. The purpose is transfer and workload measurement, not another style exploration.

## Constraints

- Use the existing `SceneStage`, `Card`, `Stamp`, `Arrow`, `MiniCar` or `SystemIcon` vocabulary where applicable.
- Use Everyman only as a reaction or emphasis marker.
- Create no new character art unless the story is otherwise impossible to read.
- Do not build a scenic hand/object interaction.
- Align scene boundaries to the final voiceover before visual assembly.
- Keep the mechanism legible from diagrams, state changes, comparisons or a decision structure.

## Measurements

- Research and source-check time
- Script and voiceover time
- Scene-manifest time
- New graphic-primitive time
- Remotion assembly and correction time
- Full render time, recorded separately
- Reused versus newly created components

## Pass criteria

- A different topic fits the architecture without copying the wrong-fuel screen content.
- At least 70 percent of the visual system is reused.
- No shot depends on exact character/prop contact.
- Representative diagnostics pass without structural restaging.
- The measured workflow indicates a credible path toward eight owner-hours per weekly episode.

## Decision after test

- **Pass:** Treat the systems-explainer composition as the channel production baseline and formalize its scene manifest.
- **Partial:** Revise only the primitives that caused repeated manual repair, then repeat with a third topic.
- **Fail:** Reduce visual density or reconsider the episode length before adding more automation.
